## Validated behavior

- Automatic phone presentation at `390 × 844` with touch emulation.
- Touch-capable wide desktop policy remains desktop in automatic mode.
- Explicit `auto`, `mobile` and `desktop` presentation override contract.
- Mobile runtime context starts before game composition and binds after the canonical camera controller is created.
- Desktop blocker is hidden only after successful mobile runtime initialization.
- `touch-action: none` is scoped to the active game canvas and restored when mobile input is disabled or destroyed.
- One-finger touch promotes from `TAP_CANDIDATE` to `ORBIT` after the deterministic movement threshold.
- Two-finger touch promotes to latched `MULTI`, emits centroid pan and pinch zoom, and does not demote until all participating pointers end.
- Pointer cancellation, capture loss, blur, hidden document, profile disable and destroy clear transient gesture state.
- The browser smoke observes native touch-derived `pointerdown`, `pointermove` and `pointerup` events rather than synthetic DOM dispatch.
- Existing desktop mouse input remains owned by the existing `src/game.js` handlers.
- Touch-to-build remains disabled. Existing touch guards in `src/game.js` remain in place.
