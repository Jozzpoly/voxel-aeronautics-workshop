## Implemented compatibility work

### 1. Executable no-origin release smoke

Added `tests/run_mobile_offline_release_smoke.mjs` and package command:

```text
npm run browser:smoke:mobile:offline
```

The smoke:

- builds the official single-file release;
- attempts local-file execution and falls back to a controlled opaque `about:blank` document when the host blocks `file://`;
- forces the `window.localStorage` getter to throw `SecurityError`;
- records every network request;
- checks the release marker, VAW kernel, mobile context, command port, runtime shell and flight controls;
- verifies memory-storage fallback;
- fails on a visible fatal overlay caused by product code;
- writes JSON diagnostics and a screenshot under `.agent-validation/mobile-offline-release-smoke/`.

The current container blocks local WebGL and localhost browser access administratively. The smoke therefore returns the documented `ENVIRONMENT` classification locally, but confirms all compatibility conditions reached before WebGL creation:

- `storageGetterThrew: true`;
- `storageKind: memory`;
- single-file release mode detected;
- required mobile and renderer modules initialized;
- zero application network requests.

### 2. Renderer profile inventory and registration

`src/game/visual-renderer-profiles.js` is now:

- part of the official embedded source inventory;
- loaded before its consumers;
- self-registering in browser execution;
- no longer recovered through synchronous browser XHR.

The duplicate synchronous XHR fallback was also removed from the visual parity diagnostic path.

### 3. Explicit storage capability

Added `src/game/storage_capability.js` as `game.storage-capability`.

The capability:

- safely probes native storage inside `try/catch`;
- provides a memory-backed fallback;
- exposes persistence and storage-kind metadata;
- degrades to memory if an initially available adapter later throws;
- is injected into mobile profile/runtime shell, career, workspace, blueprint and visual composition services.

No global localStorage shim is installed, `window.localStorage` is not redefined, and no new ad-hoc `window.VAW_*` authority was introduced.

### 4. Zero-request packaged startup

The single-file release explicitly disables external Visual Asset Pack resource loading. Procedural visuals remain the failure-safe renderer fallback.

Pack loading remains available in development/non-packaged execution, but packaged startup and packaged reload do not call `fetch` or GLTF loading for external paths.

### 5. Independent source inventory contract

Added `tools/release_source_contract.py` and mutation tests.

The contract independently scans runtime JavaScript under `src/foundation`, `src/runtime`, `src/game` and `src/game.js`, then rejects:

- missing runtime files;
- duplicate classifications;
- incorrect mobile auxiliary classification;
- invalid load ordering;
- nonexistent inventory entries.

Mutation tests prove that removing either renderer profiles or mobile flight controls from the builder inventory is detected even when builder and manifest would otherwise agree with each other.

Current official release inventory:

- embedded application sources: **70**;
- source manifest files: **168**;
- source parity: **OK**.

### 6. Flight-control lifecycle hardening

The native browser smoke now covers:

- simultaneous dual-stick input;
- positive and negative axes;
- rapid direction reversal;
- independent release of one stick;
- `lostpointercapture`;
- `pointercancel`;
- both LIFT/ROLL pairs;
- landscape and portrait transitions;
- neutral state after release;
- inactive controls after RETURN TO WORKSHOP.

`mobile-flight-controls` now neutralizes active actions on `orientationchange`, preventing a held action from surviving a phone rotation.

The useful PR #7 test intent was integrated and expanded on this branch. Its one-time patcher was removed.

## Remaining real-device gate

Test the exact official-builder HTML on Android without an HTTP server:

1. Open the downloaded HTML from the phone file manager/browser.
2. Confirm no fatal overlay appears.
3. Enter the workshop and place/remove a part.
4. Launch the Core craft.
5. Verify both sticks simultaneously.
6. Verify every positive and negative flight axis.
7. Release one stick while holding the other; the released axes must neutralize independently.
8. Rotate portrait ↔ landscape while touching controls; no action may remain stuck.
9. Trigger interruption/cancel scenarios where practical, then confirm neutral state.
10. RETURN TO WORKSHOP; controls must deactivate and BUILD must be restored.
11. Reload/reopen offline and repeat the startup check.
12. Record browser/device version, exact commit, HTML SHA-256, JSON diagnostics and screenshots/video.

Only after this checklist passes may the project status advance to **MOBILE PLAYABLE MVP VALIDATED**.
