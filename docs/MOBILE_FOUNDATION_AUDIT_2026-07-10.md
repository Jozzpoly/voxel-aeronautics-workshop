The current changes remain presentation/bootstrap-only. They do not alter Blueprint, CraftModel, compiler, runtime assembly, physics or flight-control authority.

## Decisions retained

- Mobile is an adapter over the existing game, not a separate implementation.
- Touch capability does not automatically imply phone presentation.
- A wide hover-capable touch laptop remains desktop in `auto` mode.
- Presentation override is local UI state and never craft data.
- The runtime shell owns lifecycle only; it does not own camera, build or flight behavior.
- The existing build and control-action boundaries remain authoritative.

## Decisions corrected during audit

### 1. Blocker visibility

The first runtime-shell version relied on the HTML `hidden` attribute while repository CSS explicitly sets `#desktop-required { display:flex }` below 720 px. The implementation now sets explicit inline `display:none` or `display:flex`, plus `hidden` and `aria-hidden`, so the result is deterministic.

### 2. Loader versus release sources

Adding mobile modules directly to `APP_SOURCES` broke the strict loader-order contract checked by `tests/static_check.py`. The corrected release architecture keeps `APP_SOURCES` identical to the `index.html` loader and introduces `BOOTSTRAP_AUXILIARY_SOURCES` for modules dynamically requested by bootstrap and embedded before bootstrap in single-file releases.

### 3. Bootstrap failure policy

The first bootstrap integration treated missing XHR/mobile modules as a fatal startup error. That was unsafe for headless/startup-smoke environments. Bootstrap now degrades to a desktop-capable `runtime.mobile-context` with `available:false` when auxiliary loading is unavailable, while releases embed the modules and normal served development can load them.

## Remaining MT0 risks

1. Synchronous XHR is currently used only as a served-development fallback. It is acceptable as a temporary bootstrap bridge, but should disappear once the canonical loader directly includes a generated auxiliary-source mechanism or the loader architecture is revised deliberately.
2. The existing desktop-only blocker may flash briefly before bootstrap initializes on narrow screens.
3. No browser test currently proves that a real mobile viewport reaches `data-vaw-presentation="mobile"` and hides the blocker.
4. No test currently proves single-file release startup with the embedded auxiliary modules.
5. The source manifest must be regenerated by repository tooling; it must not be edited manually.

## Following gate: MT2A pointer ownership

Implement a pure `game.mobile-touch-controller` before wiring gestures into `game.js`.

Required state-machine properties:

- pointer ID has one owner;
- one-finger candidate tap promotes to orbit only after threshold;
- second canvas pointer permanently cancels tap eligibility and promotes to pan/pinch;
- gesture promotion does not demote until all participating pointers end;
- cancel, capture loss, blur, hidden document, mode change and destroy clear state;
- controller emits camera/build intents through callbacks and never mutates gameplay state directly.

## Prohibited shortcuts

- Do not remove touch guards from `game.js` before pointer ownership exists.
- Do not synthesize right-click as the primary remove UX.
- Do not place mobile gesture logic directly into physics or CraftModel.
- Do not weaken loader-order, release-source or architecture tests.
- Do not declare MT0B closed without browser and release evidence.
